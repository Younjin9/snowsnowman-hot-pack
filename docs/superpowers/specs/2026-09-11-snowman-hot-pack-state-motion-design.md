# 눈사람 핫팩 상태 표현 및 똑딱이 움직임 디자인

## 목표

액체 상태와 결정 상태를 즉시 구분할 수 있게 만들고, 결정이 금속 똑딱이에서 시작해 눈사람 전체로 퍼지는 과정을 명확하게 표현한다. 금속 똑딱이는 포인터 드래그와 휴대폰 기울기로 움직일 수 있어야 한다. 모자는 눈사람 머리에 실제로 씌워진 형태로 다시 구성한다.

## 선택한 표현 방식

CSS 확산막과 DOM 결정 입자를 결합한다. Canvas와 SVG 필터는 추가하지 않는다. 기존 단일 HTML 구조와 반응형 동작을 유지하면서 GPU 친화적인 `transform`과 `opacity` 중심으로 애니메이션한다.

## 액체 및 결정 상태

- 준비 상태의 머리와 몸통은 배경이 충분히 비칠 정도로 투명하게 표현한다.
- 비닐 가장자리, 접합선, 얇은 반사광은 준비 상태에서도 유지해 제품 외곽을 알아볼 수 있게 한다.
- 결정화가 시작되면 현재 똑딱이 위치를 확산 원점으로 사용한다.
- 반투명한 흰색 확산막이 똑딱이 주변에서 시작해 몸통을 채우고, 이어서 목 연결부와 머리까지 퍼진다.
- 결정 입자는 확산막의 진행 방향을 따라 지연 생성된다.
- 결정화 완료 상태에서는 머리와 몸통 내부가 거의 불투명한 흰색이 된다. 접합선과 얼굴, 소품, 금속 똑딱이는 계속 선명하게 보인다.
- 녹이는 동안 흰색 확산막과 결정 입자가 함께 옅어지고 준비 상태의 투명도로 돌아간다.

## 금속 똑딱이 드래그

- 마우스와 터치 입력을 Pointer Events로 통합한다.
- 똑딱이는 몸통 내부의 안전 영역에서만 움직인다.
- 드래그 거리가 6px 미만이면 결정화 클릭으로 처리한다.
- 6px 이상 움직이면 드래그로 처리하고 결정화를 시작하지 않는다.
- 이동 위치는 CSS 변수 `--disc-x`와 `--disc-y`로 전달한다.
- 결정화 중에도 똑딱이 위치는 유지하지만 추가 입력은 잠근다.

## 휴대폰 기울기

- 모바일 환경에서 `기울기 켜기` 버튼을 제공한다.
- iOS에서는 사용자 버튼 클릭 안에서 `DeviceOrientationEvent.requestPermission()`을 호출한다.
- 권한이 허용되면 `beta`와 `gamma` 값을 안전 영역 내 목표 좌표로 변환한다.
- 똑딱이는 목표 좌표를 즉시 따라가지 않고 감쇠 보간으로 부드럽게 이동한다.
- 권한이 거부되거나 센서를 지원하지 않으면 상태 문구로 알리고 포인터 드래그는 계속 사용할 수 있게 한다.
- 모션 축소 설정에서는 감쇠 움직임을 단순화하고 과도한 흔들림을 사용하지 않는다.

## 모자 구조

- 모자의 왕관과 챙을 모두 머리 앞쪽 레이어에 배치한다.
- 왕관 아래쪽이 머리 윗부분을 충분히 덮어 머리가 모자를 뚫고 나오지 않게 한다.
- 챙은 왕관보다 앞에 놓고 이마 곡선을 좁고 얕게 감싼다.
- 방울은 왕관 오른쪽 끝에 붙여 아래쪽으로 자연스럽게 처지게 한다.
- 모자 전체 폭과 위치를 머리 비율에 맞춘다.
- 소품의 빨간색 팔레트는 유지하되 챙과 왕관의 명암 차이로 구조를 구분한다.

## 오류 및 상태 안내

- 센서 권한 요청 중, 허용, 거부, 미지원 상태를 `aria-live` 문구로 전달한다.
- 센서가 실패해도 결정화와 드래그 기능은 정상 동작해야 한다.
- 중복 타이머와 중복 센서 리스너가 생기지 않도록 초기화와 활성화 함수를 한곳에서 관리한다.

## 검증 기준

- 준비 상태가 기존보다 명확하게 투명하다.
- 결정화 완료 상태가 거의 흰색이며 준비 상태와 즉시 구분된다.
- 흰색 확산이 현재 똑딱이 위치에서 시작해 몸통과 머리로 순차적으로 퍼진다.
- 똑딱이를 포인터로 끌 수 있고 몸통 밖으로 나가지 않는다.
- 짧은 클릭은 결정화를 시작하고 드래그는 결정화를 시작하지 않는다.
- 지원되는 휴대폰에서 권한 허용 후 기울기에 따라 똑딱이가 움직인다.
- 센서 거부 또는 미지원 환경에서도 드래그와 결정화가 동작한다.
- 모자 왕관과 챙이 머리 앞에서 이마를 자연스럽게 덮고 머리가 모자를 뚫지 않는다.
- 모바일, 가로 화면, 다크 모드, 모션 축소 설정에서 화면이 깨지지 않는다.
